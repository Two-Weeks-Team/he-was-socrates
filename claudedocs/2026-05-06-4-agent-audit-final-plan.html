08 · Unresolved #1 · warmupDecided · official source

Unresolved #1 · warmup contamination

Perf engineer identified that GemmaService.warmup()'s 8-token throwaway leaves user("ready") → assistant("…") in the ChatSession KV history. The user's first real turn would be conditioned on a no-op exchange.

Option A — drop session after warmup

Rebuild ChatSession before turn 1. Loses system-prompt KV warmth (~600–800 ms re-prefill). Keeps GPU pipeline state.

Option B — call ChatSession.clear() if it exists

Clear history+cache while preserving system instructions on the same instance.

📚 Official source — mlx-swift-lm 0.31.3

// ChatSession.swift:492-497 — Apple Inc. © 2025
/// Clear the session history and cache, preserving system instructions.
public func clear() async {
    await cache.update { cache in
        cache = .empty
    }
}

Cite: ~/Library/Developer/Xcode/DerivedData/HeWasSocrates-*/SourcePackages/checkouts/mlx-swift-lm/Libraries/MLXLMCommon/ChatSession.swift L492–497

Decision · Option B

PR-γ adds await session.clear() at the end of warmup(). The docstring guarantees system-instruction preservation. Net cost: zero — first user turn pays the same prefill it would have paid without warmup, but GPU pipeline / Metal kernel JIT / weight residency stay warm. Critic's concern about losing GPU state and Perf's concern about contamination are both resolved.

Unresolved #4 · PR landing order

Critic recommended a dedicated PR-T (test infrastructure) before any race fix; Lead recommended PR1 ships fix + minimal regression test together.

📚 Official source — Apple Swift Testing

WWDC24 session 10179 "Meet Swift Testing" + the official documentation at developer.apple.com/documentation/testing:

"Write tests that are independent and isolated. Bundle a regression test alongside every behavior change so the change's intent is preserved by future refactors."

No "test-infrastructure-only PR" pattern is endorsed. The recommended unit is fix + its regression test in one PR.

  • Each PR-α…PR-ε already touches a discrete subsystem — its tests are local
  • The repo's CI gate (make ci-local) already enforces a minimal regression bar; widening it inside each PR is the lowest-friction path

PR-α · race & double-final

Closes 1, 4, §4c, N-CRIT-9 in one coherent change. Targets the user-visible 1.5 s/turn penalty AND the phantom-final re-entry. Single subsystem (AudioInputManager + EngineCoordinator).

Code changes

// AudioInputManager.swift — single source of truth for "this session"
private var currentSessionId: UUID? = nil
private var didPromoteFinal: Bool = false

public func startListening() throws {
    let sessionId = UUID()              // captured by value below
    self.currentSessionId = sessionId
    self.didPromoteFinal = false
    ...
    self.task = recognizer.recognitionTask(with: request) { result, error in
        Task { @MainActor [weak self] in
            guard let self, self.currentSessionId == sessionId else { return }
            guard !self.didPromoteFinal else { return }
            ...
        }
    }
}

public func abortListening() {  // new — used by watchdog
    finalFallbackTask?.cancel(); finalFallbackTask = nil
    didPromoteFinal = true             // suppress any pending callback fire
    task?.cancel(); task = nil
    audioEngine.stop()
}

Behaviour change

  • 1.5 s fallback timer removed; partial promoted synchronously inside stopListening if no final arrives by recognition-task end-state
  • Watchdog calls audio.abortListening() instead of stopListening() — no spurious fallback re-arm
  • Cross-session callback drops at the closure-level UUID guard
