TL;DR

4명의 독립 심사 에이전트가 만장일치로 "전면 피벗하지 말 것"으로 수렴. 8일 안에 코드베이스를 갈아엎으면 더 나쁜 결과물을 출품하게 된다. 합의안: ① A의 코드베이스 유지 (65 tests, CI green, frozen contract — 버릴 수 없는 자산) ② B의 "Gemma 4 = $0 forever, on-device-by-entitlement"를 오프닝 framing으로 graft (abstention은 "신뢰성 증명"으로 강등, 헤드라인 아님) ③ 주 트랙을 Technical로 재지정 (macOS-only가 Impact 트랙의 reach를 죽임) ④ long-context recall이 STUB인 것을 절대 과대주장 금지 (credibility landmine — 가장 위험) ⑤ D-8은 코드가 아니라 포장 (Wireshark가 0 패킷 잡는 영상 + DMG + 스크린샷 + Kaggle 페이지). 추정 수상가능성: A 그대로 ~3-5% / 전면 B 피벗 ~1-2% / 하이브리드(A+B framing) ~7-10%. Scenario C(라이프로깅 마니또)는 D-8 해커톤엔 불가능 — 다만 wondering log이 이미 그 씨앗이므로 writeup "Future direction"에 심을 가치 있는 product vision.

  6. D-8 우선순위 = 포장 — 코드 아님. 영상(Wireshark 0 패킷 + abstention 실시간) + 노타라이즈 DMG + 앱 스크린샷 5-7장 + Kaggle 페이지. category-leading engine이라도 shippable demo 없으면 "working demo" + "use-case communication" 점수 0 = rubric의 2/3.

2. 세 시나리오 비교

Scenario A — 현 트랙 그대로 (status quo)

무엇: macOS 풀스크린 소크라테스 흉상, push-to-talk, "답하지 않는 것이 제품", Impact:Education + Technical, Korean-first, macOS 26+ only.

강점: 완성됨 (65 tests, CI green) · "abstention is the product"는 Godin-test 통과하는 기억에 남는 포지셔닝 · NO-CLOUD-by-entitlement는 거의 아무도 못 가진 검증 가능 차별화 · 192ms TTFT + 24× systems trick (bench JSON 공개) · 한국어 정체성 = authenticity.

약점: macOS 26+ only = Impact 트랙 reach 거의 disqualifying · long-context recall STUB (과대주장 시 landmine) · multimodal = voice+talking head only (image/video input 없음 → Technical 심사가 multimodal 무겁게 보면 타격) · D-8에 영상/DMG/스크린샷/Kaggle 페이지 전부 미완.

수상가능성: 그대로 ~3-5% (any tier). framing graft 시 ~7-10%.

Scenario B — Gemma 4 zero-cost 전면 피벗

무엇: "Gemma 4 = $0 forever, no servers"를 중심으로 재정렬, 그 강점이 가장 잘 먹히는 트랙/문제영역 선택 (저자원 지역 무료 교육 / 기후-datacenter 에너지 0 / $0-운영 health triage / 무연결 환경 offline assistant). 비용: macOS-only + Korean-only + refusal 훅 폐기, narrative 재구축, 어쩌면 cross-platform 데모 신규 — 8일 안에.

강점: 추상적으로는 더 큰 impact 스토리 · "constrained environments" 직격.

약점: "$0 forever"는 입장료지 moat 아님 (모든 on-device 출품작이 주장) · 8일 재구축 = 덜 다듬어진 결과물 · 가장 붐비는 레인(generic offline Gemma wrapper)에 늦게 진입 · sharp identity 상실 · 완성된 B+ engine을 버리고 C- 받기 · 분배 계획·타겟 커뮤니티 없음.

수상가능성: ~1-2% (전면 피벗). 만장일치 비추천

Scenario C — 항상-켜진 라이프로깅 "마니또" 비서 (사용자 신규 제안)

무엇: 하루종일 화면 기록 + 음성 청취 + 모든 일상 기록, Qdrant 등 로컬 벡터 DB로 메모리 관리 (OpenClaw / Hermes / Rewind.ai 류), 조용히 항상 곁에 있는 비용 0 개인 비서. 마니또(secret-friend) 정서.

해커톤 적합성 (D-8): 불가능 — ScreenCaptureKit + 새 entitlement (com.apple.security.device.screen-capture 또는 TCC grant, 현재 없음) + 상시 마이크 (현재 push-to-talk only) + Qdrant 통합 + 메모리 retrieval 파이프라인 = 수개월 프로젝트. 8일에 출품 불가.

현 invariant과의 긴장: NO-CLOUD는 유지 가능 (Qdrant 로컬 실행). 그러나 "모든 것을 기록"은 "abstention/minimal/refuses-to-answer" thesis와 정면 충돌 — 미니멀 흉상에서 surveillance-grade 라이프로거로의 정체성 전환. 1-bit halftone 미학·"답하지 않음" 헤드라인과 양립 어려움.

그러나 — 이미 씨앗이 있다: WonderingLog actor에 append · surface(matching:max:) · exportJSON · contentFingerprint (SHA-256 dedup)가 이미 구현됨. surface_past_wonder 함수 + Gemma 4 256K context = "다년 회상"의 축소판. 즉 C는 피벗이 아니라 이미 있는 것의 확대. "14개월 전 자네가 '얼음이 왜 미끄러운지' 물었지 — 그 답이 비 오는 도로에도 통하는가?"라는 writeup의 예시가 정확히 C의 미니어처.

판정: D-8 해커톤엔 제외. 다만 writeup "Future direction"에 심을 가치 있는 product vision — wondering log → 다년 회상 → "ambient memory companion, 여전히 $0, 여전히 on-device, 여전히 0 byte egress". 아키텍처에 다리가 있음을 보여주고, stub이 "데모용 stub"이 아니라 "실제 제품의 토대"임을 입증. post-hackathon 1순위 product 방향으로 별도 design doc 가치 있음 — 단 지금은 아님. Rewind.ai($$$/subscription)·cloud assistant 대비 "$0 forever because on-device"가 진짜 차별화.
