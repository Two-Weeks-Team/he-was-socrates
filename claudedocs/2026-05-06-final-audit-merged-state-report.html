PR-α — Double-final Race + ko-KR Penalty Removal

Bug

SFSpeechRecognizer can fire isFinal=true multiple times for one utterance (Apple Forum 125279). Watchdog stop and natural endpoint could both call onFinal, double-feeding the orchestrator and corrupting turn state.

Fix

  • Per-session currentSessionId: UUID + didPromoteFinal: Bool captured by value in recognition closure.
  • New abortListening() tears down the session without firing onFinal — used by watchdog.
  • Removed unjustified 1.5s ko-KR endpointing penalty (Apple does not document a ko-KR penalty).
// AudioInputManager.swift
recognitionTask = recognizer.recognitionTask(with: request) { [weak self, sid = currentSessionId] result, error in
  guard sid == self?.currentSessionId, !(self?.didPromoteFinal ?? true) else { return }
  // promote final exactly once per session
}

Tests: doubleFinalCallbackPromotedOnlyOnce, abortListeningSuppressesOnFinal, sessionIdMismatchIgnored.

PR-β — Hang Killers

Bug

Three observed hang states with no recovery: (1) .bootstrapping > 10 min if Gemma weights missing; (2) .failed never auto-rearms; (3) TTS interruption mid-utterance leaves state stuck on .speaking.

Fix

  • Per-phase watchdog budgets: .bootstrapping 600s, .thinking 60s, .speaking 30s, .failed 5s auto-rearm to .idle.
  • TCC deadline: SFSpeechRecognizer.requestAuthorization raced against 10s deadline via WithTaskGroup.
  • onUtteranceCancel wired through AVSpeechSynthesizerDelegate.didCancel → resets viseme + Phase.
// EngineCoordinator.swift
private func runWatchdogBody(elapsed: Duration) async {
  switch phase {
  case .bootstrapping where elapsed > .seconds(600): fail(.bootstrapTimeout)
  case .failed       where elapsed > .seconds(5):   transition(.idle)
  case .thinking     where elapsed > .seconds(60):  fail(.turnTimeout)
  default: break
  }
}

Tests: bootstrappingExceeds600sFailsWithTimeout, failedPhaseAutoRearmsToIdleAfterBudget, onUtteranceCancelResetsVisemeAndPhase, tccDeadlineRaceCutsAt10s.

PR-γ — Warmup + Caches

Goal

Cut first-turn latency. Initial measurement: 9–11s/turn (cold load + cold KV cache + voice lookup + viseme image lookup + formatter alloc).

Fix

  • ChatSession warmup: bootstrap runs a throwaway turn, then chatSession = nil drops history. ModelContainer (GPU pipeline) is preserved.
    Note: session.clear() tripped Sendable strict-concurrency from an actor boundary; drop-reference is the safe equivalent (mlx-swift-lm ChatSession.swift:492-497).
  • Voice cache [String: AVSpeechSynthesisVoice] + NSLocale.currentLocaleDidChangeNotification invalidates on locale switch.
  • VisemeImageCache preloads the 6 viseme PNGs at bootstrap.
  • ISO8601DateFormatter hoisted to nonisolated(unsafe) static let (Apple Foundation thread-safety docs).
  • Reduce-Motion Tier-3 500ms square-wave talking cue per viseme-best-practices §7.6.

Latency floor — see Slide 21 for the live N=10 measurement; pre-PR-γ first turn was 9–11 s, post-warmup steady-state is ~6.4 s/turn (median, M1 Max MacBook Pro 64 GB).

PR-θ — Error Surface (F8 + F9)

F8 — supportsOnDeviceRecognition gap

Setting requiresOnDeviceRecognition = true without first checking SFSpeechRecognizer.supportsOnDeviceRecognition caused silent failure on locales where the on-device model is not installed (e.g. some Mac Mini configurations). Per Apple's NO-CLOUD invariant, the network fallback is forbidden.

F9 — Audio interruption

AVAudioEngine raises NSError from AVAudioSession-class interruptions (call routing, kAudioSessionRouteChangeReason). These were swallowed into a generic audioRuntimeError.

Fix

  • Precheck recognizer.supportsOnDeviceRecognition at startup → surface as sttOnDeviceUnsupported with recovery hint pointing users at System Settings → Speech Recognition.
  • New static EngineCoordinator.failureKey(for: NSError) -> String: maps kLSRErrorDomain code 1101 → sttOnDeviceUnsupported; AVAudio* domains → audioInterrupted; default → audioRuntimeError.
  • FailedMessage extended in app with Korean recovery hints for both new keys.

Tests: failureKeyMapsLSRErrorTo_sttOnDeviceUnsupported, failureKeyMapsAVAudioInterruptionTo_audioInterrupted, failureKeyDefaultsTo_audioRuntimeError.

PR-ι — Sandbox + VoiceOver (F18; F16 deferred)

F18 — CFBundleSpokenName

Without CFBundleSpokenName, VoiceOver reads "Socrates" letter-perfect ("soh-krayts"). Apple's Bundle reference documents this key as the dictionary pronunciation override:

<!-- Info.plist -->
<key>CFBundleSpokenName</key>
<string>He Was SOCK-ruh-teez</string>

F16 — device.microphone entitlement: DEFERRED

The original audit recommendation cited com.apple.security.device.microphone. Verification against Apple's App Sandbox Entitlement Reference showed this key is NOT in the official list — only com.apple.security.device.audio-input is documented. The audit-agent's source was a forum post, not Apple official.

Per the user's "official-sources-only" directive, the change was NOT applied. The existing audio-input entitlement is correct and sufficient. F16 is closed as deferred-not-applicable.

PR-κ — Swift 6 App Target Alignment (F15)

Why F15 matters

The engine package declared swift-tools-version: 6.1 with SWIFT_STRICT_CONCURRENCY: complete. The macOS app target was on SWIFT_VERSION: "5.9". Mismatched language modes silently demote engine warnings to compile-time accepts in the app's own use of those types — masking real Sendable violations until runtime data-races.

Fix (settings-only)

# apps/macos/HeWasSocrates/project.yml
settings:
  base:
    SWIFT_VERSION: "6.1"     # was "5.9"
  • No source changes needed — PR-η already prepared the engine for strict-concurrency under 6.1.
  • make xcodeproj regenerates cleanly; make app BUILD SUCCEEDED with zero new diagnostics.
  • App + engine now compile under the same language mode, end-to-end.

Reference: Apple Swift Evolution per-target language mode guidance + Swift Forums consensus on workspace alignment.
